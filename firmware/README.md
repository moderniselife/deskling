# Deskling firmware

ESP-IDF 6.1 + LVGL 9.6 for the Guition JC8012P4A1C (ESP32-P4 + ESP32-C6, 10.1" 800×1280 panel), shown in landscape at 1280×800.

```
main/
  main.c            boot: NVS, board, UI, network
  board/            panel (JD9365 over MIPI-DSI), backlight, GSL3680 touch driver with the startup fix
  net/              Wi-Fi through the C6 + hotspot fallback, clock sync, WebSocket to the relay,
                    settings page (portal.c/html), over-the-air updates (ota.c)
  app/settings.c    Wi-Fi / relay / time zone / brightness / volume in NVS
  app/sound_synth.c Deskling's chirps, synthesized (shared with the sim and the website)
  board/audio.c     ES8311 codec + speaker over I2S
  app/model.c       parses relay snapshots, builds the messages the screen sends back
  ui/               all screens + Deskling the character (pure LVGL, also runs in sim/)
  ui/fonts/         Nunito + JetBrains Mono, generated by tools/gen_fonts.sh
config/           per-variant sdkconfig fragments (chip revision, LCD panel)
tools/release.sh  builds every variant and publishes firmware-dist
sim/                host build of the UI: renders every screen to PNG, taps buttons, checks messages
```

## Installing (no toolchain needed)

Most people never build this: open `https://<your relay>/flash` in Chrome or Edge, plug in a USB cable once, and click install. Then set up Wi-Fi and the relay on the screen. The steps are in [docs/setup.md](../docs/setup.md).

After that, everything is over the air:
- **OTA:** the screen reads `manifest.json` from `CONFIG_DESKLING_UPDATE_URL` (`https://deskling.mojolayers.com/firmware/`, which serves the `firmware-dist` branch through Cloudflare's cache; it falls back to that branch on raw.githubusercontent.com directly) when it joins Wi-Fi and every 12 h. **Settings → Firmware** installs it. A new build has 3 minutes to reach the relay (or join Wi-Fi, if no relay is set yet) before the bootloader rolls back.
- **Settings page:** `http://deskling.local` (or the IP on screen), unlocked with the 4-digit code on the screen. It covers Wi-Fi, relay, time zone, brightness, restart, and uploading an app `.bin` you built yourself.
- **Hotspot:** if Wi-Fi fails, the screen opens an open network called `Deskling-XXXX`. The settings page is then at `http://192.168.4.1`.

## 1. Building it yourself

Install [ESP-IDF v6.1](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32p4/get-started/), then:

```bash
cd firmware
idf.py set-target esp32p4   # first time only
idf.py build
idf.py -p <port> flash monitor
```

The default build is for P4 silicon v1.x with the original LCD (`config/p4r1.defaults` + `config/lcd1.defaults`). For another board, use `-DSDKCONFIG_DEFAULTS="sdkconfig.defaults;config/p4r3.defaults;config/lcd2.defaults"` and pick the fragments that match.

Wi-Fi, relay and time zone are set on the screen and stored in NVS. To bake defaults into a dev build instead, create the git-ignored `firmware/sdkconfig.defaults.local`:

```
CONFIG_DESKLING_WIFI_SSID="your-wifi"
CONFIG_DESKLING_WIFI_PASSWORD="your-password"
CONFIG_DESKLING_RELAY_URL="https://deskling-relay.<you>.workers.dev"
CONFIG_DESKLING_TOKEN="<the DESKLING_TOKEN you set on the relay>"
```

`idf.py menuconfig` → **Deskling** has the same options, plus touch axis flips, brightness, "upside down" and the update URL.

Use the USB-C port wired to the CH340 serial chip; the board has three. On macOS the port looks like `/dev/cu.wchusbserial*`, and on Windows it's a `COM` port. Power the board from a proper 5 V / 1 A or better supply.

## 2. Releases

There's no CI. Releases are built locally and published to the orphan `firmware-dist` branch. The update server at `deskling.mojolayers.com/firmware/` (the `site/` Worker) serves that branch to the installers and to screens:

```bash
. $IDF_PATH/export.sh
firmware/tools/release.sh v0.3.0             # builds 4 variants, writes manifest.json, force-pushes firmware-dist
firmware/tools/release.sh v0.3.0 --no-push   # just build into firmware/dist/
```

| Variant | Board |
| --- | --- |
| `p4r1-lcd1` | ESP32-P4 silicon v1.x, label batch below 2624 (most 2025 boards) |
| `p4r1-lcd2` | silicon v1.x, batch 2624+ |
| `p4r3-lcd1` / `p4r3-lcd2` | silicon v3.x |

Each variant has `deskling-<version>-<variant>.bin` (the app, for OTA and upload) and `deskling-<version>-<variant>-full.bin` (the whole flash from 0x0, for the installer or `esptool write-flash 0 …`). The version is in the file name, so a published build never changes and can be cached forever; only `manifest.json` moves. The version shown on the screen and compared by OTA comes from `DESKLING_VERSION`.

## Sounds

Deskling has a voice: a dozen short chirps synthesized on the fly by `main/app/sound_synth.c` (no audio files), played through the board's ES8311 codec and speaker (`main/board/audio.c`). It chirps for permission requests, questions, finished tasks, reminders, replies, ticked-off reminders, bedtime, and a soft tick on every press. **Settings** on the screen (or `deskling.local`) has a volume slider and "Quiet at night", which mutes everything except reminders between 10pm and 7am. The `deskling.local` page can also play each sound.

`tools/render_sounds.c` renders the same synth to WAV files, which is what the website plays:

```bash
cc -O2 -Imain/app tools/render_sounds.c main/app/sound_synth.c -lm -o /tmp/render_sounds && /tmp/render_sounds ../site/public/sounds
```

## 3. If something's off

| Symptom | Fix |
| --- | --- |
| Three solid colour bars, or a garbled picture | Wrong LCD revision. Reinstall from `/flash` with the other panel option (or flip `DESKLING_LCD_V1` / `V2`). |
| Boot log says `chip revision: v3.x` and it won't boot | Use the `p4r3` defaults (the browser installer does this automatically). |
| `touch controller didn't start` | Power-cycle; don't just press reset. The driver retries once, and the controller sometimes only recovers from a full power-off. |
| Touches land in the wrong place | Set the touch swap/mirror options in menuconfig. |
| Stuck on "Joining Wi-Fi…" and the log shows SDIO or transport errors | The ESP32-C6 co-processor firmware is too old for esp_hosted 3.x. Flash the C6 with the matching slave firmware from [esp-hosted-mcu](https://github.com/espressif/esp-hosted-mcu) (`slave/` project, target `esp32c6`) through the C6 UART header. |
| No sound | Check the boot log for `audio: speaker ready`. If it says the ES8311 didn't answer, the codec isn't on the shared I2C bus at 0x18. Also check the volume in Settings and that it isn't quiet hours. |
| Very weak Wi-Fi | Some units ship without an antenna on the IPEX connector. Fit a 2.4 GHz IPEX antenna. |

## Simulator (no board needed)

```bash
firmware/tools/run_sim.sh sim-out --frames
```

This builds the same UI code for Linux or macOS, plays the fixture snapshots in `sim/fixtures/`, taps the buttons, checks that the right messages go to the relay, and writes screenshots plus animation frames to `sim-out/`. It needs cmake and a C compiler.

`tools/bench_ui.sh` builds the same UI with device-like rendering and times every frame of the main interactions (screen changes, the notification pull-down, alerts, moods). `tools/bench_ui.sh frames before/` dumps the frames too, and `tools/frame_diff.py before/ after/` shows exactly which frames a change touched. On the board, the log prints redraw timings every 5 s while things move, and the setup page shows the latest ones.

## Fonts

`tools/gen_fonts.sh` regenerates `main/ui/fonts/` from Nunito and JetBrains Mono. Both are SIL Open Font License; see `main/ui/fonts/OFL-Nunito.txt`.
